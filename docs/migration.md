# 备份与旧版迁移

## 手机本地备份

在设置中导出 JSON 备份，选择系统文件位置；恢复时选择之前导出的文件。备份仅包含本地记录，不包含聊天历史、设置、DeepSeek API Key、HITA 授权关联或旧电脑连接凭据。

卸载或清除数据前，先导出并核对备份文件。恢复记录后，重新保存自己的 API Key，并确认通知权限与提醒。HITA 有独立数据库，使用 HITA 自己的导出／导入功能备份。

导入保留记录标识，已存在的标识一律跳过，包括手机已经删除的记录；不会覆盖本机编辑，也不会重新恢复已删除事项。结果反馈导入、跳过和忽略删除的数量。备份文件上限为 16 MB、20,000 条记录。

## 从 0.7.x 电脑版迁移

1. 停止旧电脑程序的服务，保留整个旧 `data` 文件夹作为备份。
2. 将其中的 `assistant.db` 复制到手机上能通过文件选择器打开的位置。停止服务后复制，避免 SQLite WAL 中尚未合并的改动遗漏。
3. 在随手记事设置中选择旧电脑数据库导入入口，选择该文件。
4. 查看导入结果，核对任务、备忘和重要日期。模型 Key 和中转／配对配置不导入。

迁移只读取旧 `planner_records` 表中未删除的已保存记录。旧聊天原文和未写入该表的 HITA 日程不能通过此入口恢复；HITA 请使用自己的备份功能。

导入在手机完成，不需要再连接旧服务，也不改变电脑上的原数据库。不要删除旧备份，直到已确认需要的记录完整。

旧聊天渠道、Cloudflare 账户、Worker 或购买过的域名不再是本地版使用前提。本项目不会自动删除你账户中的资源；确认不再需要时，可自行在对应服务控制台停用。

## 签名不兼容

预览 APK 的不同 CI 构建可能采用不同测试证书；同一次发布的随手记事和 HITA 两款包签名匹配。Android 提示无法覆盖安装时，先完成记录备份再卸载重装，不要直接清除数据。未来切换为正式签名时也可能需要迁移。
