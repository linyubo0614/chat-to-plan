# 番茄计划：官网与安卓同步问题

更新日期：2026-10-11。安卓版本 v7.7.0，微信授权登录。以下真实账号结果由用户在自己的电脑和手机验证；云环境没有账号登录状态。

## 已确认的对照结果

| 创建来源与记录 | 官网 | 手机同步后 |
| --- | --- | --- |
| 手机手动创建“手机同步对照测试” | 能出现 | 原记录存在 |
| 官网手动创建“网页同步对照测试” | 存在，手机同步后未被覆盖删除 | 没出现 |
| 官网手动创建当日“网页今日同步测试” | 存在 | 没出现 |
| 本项目创建“对话计划授权验证”及测试分类 | 写入并读回核对成功，手机同步后记录仍存在 | 没出现 |

用户确认两端为同一账号，手机“同步数据”显示成功。在当天待办、全部分类和逾期计划中也没有找到测试记录。红色感叹号文档图标实际打开的是“逾期计划”，不能用它推断同步错误。

这些结果确认：当前账号的手机新增能到官网，而官网新增没有在手机出现。官网正常手工创建也会复现，因此问题范围超出了助手提交脚本。尚不能断言手机只上传、服务端没有下发或手机代码丢弃了记录；界面上的“同步成功”不能区分这些原因。

原始“对话计划授权验证”已被用户修改。脚本报“测试记录已被修改，未覆盖”是已有保护正常生效，与手机下载问题不同。不得覆盖、删除或自动重建用户修改后的记录来消除报错。

## 当前适配器实际写入的模块

`tools/tomato_bridge.py` 调用官网自身 `$api.getSyncList`，实际协议为 `/tomato/syncData/listInfo`。写入对象是官网清单待办。尽管解析模型支持 `kind=memo`，当前适配器把它映射成带正文的清单记录，**没有实现安卓独立“备忘录”模块写入**。

手机截图及 v7.7.0 Manifest 中的 `ui.memo.MemoCreateActivity`、`MemoCategoryManageActivity` 等证明该模块单独存在；不能把它与清单待办视为同一目标。此前文档把官网记录称为测试备忘，范围描述不准确，现已修正。

当前 `written` 回执由网页连接端写入、官网读回后提交。它只能证明官网清单保存，不能证明手机同步或独立备忘录保存。手机端未验收前，不应把这条交付路径用于依赖手机备忘录的日常自动记录。

## 下一步与成功标准

停止重复同一新建/刷新试验。要定位根因，需要手机 v7.7.0 一次授权同步的实际请求与处理结果，或者厂商对官网创建记录同步范围的明确说明。诊断优先只读，对照手机创建与官网创建的测试记录在下载集合及数据结构中的差异，不上传个人数据、Cookie、JWT、原始请求头或浏览器配置。

未取得上述证据前，不发布声称“已修复手机同步”的安装包，也不通过清空数据、退出账号或覆盖云端集合进行盲目排查。若官网清单接口不能写入真正的备忘录，应单独实现已验证的备忘录接口或官方授权导入路径；不能用改文案代替功能实现。

验收须分别满足：手机独立“备忘录”出现正文与分类；手机待办出现日期/分类正确的事项；重试不重复；用户改动不会被覆盖。当前这些目标尚未通过。
